# v0.0.31 - a password change ends the sessions the old password minted

Changing a password now signs out every other session of that account,
closing audit finding F3 (see Audit.md in the repository).

## What changed

- `PUT /api/me/password` (change your own password) deletes every
  *other* session of your account in the same step that stores the new
  hash. The session you are changing the password from stays open - it
  authenticated this very request - and the settings page says so in
  the confirmation.
- An administrator resetting a password deletes *every* session of the
  target account. A reset is called for precisely when an account may
  be compromised, so nothing survives it.
- Sessions are also removed when a user is deleted (this was already
  the case; it now shares the same statement batch discipline).

## Why it matters

Before this release, a session cookie stolen earlier (a copied cookie
jar, a leaked token from a browser extension) survived a password
change - the standard incident response did nothing to it. Now
rotating the password closes the door it was meant to close.

## Action required

None. If you share an account with someone, expect their devices to be
signed out after a password change; signing in again restores them.
