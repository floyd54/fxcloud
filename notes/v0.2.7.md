# v0.2.7 - the page admits when JavaScript is off

A field report closed a five-day mystery: on some devices (reported:
Google Pixel) JavaScript is **disabled by default for freshly
installed web apps**, and the install dialog offers no switch. The
symptoms are indistinguishable from a dead server - tabs that do not
react, English labels in a German browser, and a sign-in that loops
back to the mask without any error, because without the page script
the form falls back to a plain browser submit and the session never
starts. Until now the page gave no signal that this state existed.

## What changed

- **`<noscript>` banner on the login page and in the app.** It is the
  one visitor who cannot run the i18n dictionaries, so the text is
  bilingual and static: it names the problem and the fix path
  (long-press the fxcloud icon > Settings > JavaScript). The banner
  is styled with the theme colors and renders without any script.
- **USERGUIDE documents the full symptom trio** in Troubleshooting -
  dead tabs, English labels, error-free loop back to the mask - plus
  the tell that separates it from the other loop (session cookie
  dropped): when the tabs react and the page is in your language, the
  cause is cookies or `http://`, not JavaScript. The "Install as an
  app" section now warns new installers about the device-dependent
  default right where they install.

## Compatibility

Pure HTML, one CSS block and documentation: no JavaScript, API,
session or crypto change. With JavaScript enabled nothing renders
differently - the `<noscript>` content only exists when the browser
has scripting off.
