# v0.4.3 - the text and markdown editor

Text files stop at a preview no more: the preview gains **Edit**, and
the app gets the editor the web has in its lightbox - with the half
the web never had, a real markdown toolbar.

- **Editor**: monospace source, the meta line (`12 lines - 340
  chars`, `* unsaved`), Save in the header, and a leave guard that
  asks save/discard/cancel - a failed save never closes over unsaved
  bytes. Loading is a fresh download with its own baseline; the
  preview's stale text is never trusted.
- **Markdown**: `.md`/`.markdown` open with a toolbar that wraps or
  prefixes at the selection (bold, italic, H1/H2, bullet, numbered,
  task list, quote, code, link) and a **Preview** toggle rendering
  the note - the web's `mdToHtml` ported line for line. The vectors
  (`tests/fixtures/md-vectors.json`,20 cases) are generated from the
  JS itself by `frontend/tests/gen-md-vectors.js`, so the two
  renderers cannot drift apart silently: blocked `javascript:`
  targets, code spans that survive bold, CRLF folding, all of it.
- **Save follows the web's rules** through `PUT /files/content`: an
  encrypted row re-encrypts under the *same* file key (the history
  keeps opening), a plaintext row under a keyed folder is promoted
  with `history=drop` (the zone write), a plaintext account writes
  plain. Every save makes the server pin the old text as a version,
  so the S5c version list now carries the editing history; a
  read-only sharee meets the server's pinned 403 as a status error,
  never a crash.
- Version stands stay read-only: no Edit next to no Rotate.

## Compatibility

The server binary is unchanged apart from its version string; no API,
no data, no manifest change.
