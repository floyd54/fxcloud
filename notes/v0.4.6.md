# v0.4.6 - the fingerprint fix, and the passkey maze documented

Two things since v0.4.5:

- **Fingerprint unlock, fixed.** "Could not store the fingerprint
  secret" after a *successful* scan: the enrollment prompt ran fine,
  then the Keystore refused the crypto. The key demanded per-use
  authentication (API 30+ `setUserAuthenticationParameters(0, ...)`),
  and per-use keys only accept a CryptoObject-bound token - the
  flow's plain prompt-then-crypto order can never provide one. A
  short authentication window (30s) on every API level instead: the
  plain prompt marks the keystore authenticated for exactly the
  window this flow runs in. Same ceremony as before, it simply
  works now.
- **The passkey-provider maze, documented to be forwarded.**
  Signing in from the Android app can fail with "Diese App
  unterstützt keine Passkeys" while the same passkey works in every
  browser - the credential provider verifies the app through
  Google's Digital Asset Links API, which follows no redirects and
  asks with the DNS-root form of the host. The user guide
  (section 12, en/de, plus the troubleshooting pointer in section
  15) now carries the full story, the receipts (Revolut's
  months-long case, Google tracker 460172858, Bitwarden's reverted
  workaround) and the operator checklist; the spec records the
  asset-links layout decision (one statement per fingerprint, Play's
  classic key first) and this deployment's status.

## Compatibility

The server binary is unchanged apart from its version string; no
API, no data, no manifest change. The AAB ships as **versionCode
10** - an update over whatever the closed track holds; the 14-day
counter is untouched (it tracks tester opt-in, not builds).
