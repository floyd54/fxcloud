# v0.4.7 - the tester-blocking register gate, unblocked

The closed test hit a wall: testers registering through the app were
refused with a message the app turned into a meaningless "Sign-up
failed (429)" - behind it a fixed budget of10 registrations per source
address per ten minutes, a number designed for a household, not for a
closed test where carrier-grade NAT hands whole tester batches a single
address.

- **Server: `FXCLOUD_REGISTER_BUDGET`** (default stays 10 - the honest
  floor for a personal cloud). The gate reads the knob; install.sh,
  both INSTALL tables, concepts/accounts.md and Audit.md document it.
  Set it on a test deployment and the wave walks through.
- **App: errors that say why.** Register and login failures now show
  the server's own reason - a rate limit carries its retry clock, and
  "retry in 328 seconds" is an instruction while "(429)" is not.
- **...and a feedback line you can actually see.** The202 activation
  hint existed in every build but sat at the bottom of a login column
  that neither scrolled nor fit - register mode plus a keyboard put
  it below the fold, so the account was created and the screen came
  back silent. The notice now sits above the form, the column scrolls,
  and the copy says what to do: an administrator has to activate the
  account before sign-in.
- **Passkey sign-in is gone from the app** (the provider maze could
  not be solved from our side: Bitwarden refuses despite fresh valid
  Google DAL fetches, Google's own path had no app-visible storage on
  the test device). The web keeps passkeys fully; the app signs in
  with password plus fingerprint/auto-unlock. The full record lives
  in the spec (passkey section) and the help guide (section12, en/de).
- **Groups slice planned** in the spec: admin groundwork, the group
  cards with roles and quota, and the group-key path to investigate.

## Compatibility

The server gains one optional knob whose default reproduces the old
behaviour exactly; no API, no data, no manifest change. The AAB ships
as **versionCode 11** - an update over the closed track's5/6/7/8/10;
the14-day counter is untouched (it tracks tester opt-in, not builds).
