# v0.4.4 - passkeys, swipes, hidden files, folder upload

The "better than the PWA" release: four things the browser tab does
that the phone now does too - one of them (passkeys) the phone does
*natively*.

- **Passkey sign-in.** The login page gains "Sign in with a passkey":
  the platform's Credential Manager runs the web's own ceremony, so
  app and browser share the same passkeys on the same rpId and land
  in the same session cookie. API 28+, the button hides below that;
  cancel and empty prompts read as words, not stack traces.
  **Server side, two deployment pieces** (see below).
- **Swipe the gallery.** The image preview moves like the PWA's
  arrows feel on a phone: sideways steps through the folder's
  previewables (tree order, stops at the ends), down closes it -
  next to the ← button and the system back. Loads carry a
  generation, so a slow image can no longer resurrect a closed
  preview and a newer load can never be overwritten by an older one
  landing late.
- **Hidden files.** Dot-entries stay out of the listing until the
  path-bar toggle or the settings switch says otherwise (default
  off, remembered, the web's rule); tree, trash and swipe gallery
  filter alike, and an all-hidden folder says so instead of looking
  empty.
- **Folder upload.** "+" gains "Upload folder": the platform's tree
  picker, walked with DocumentsContract (no new dependency), folders
  created on the way (they inherit `names_enc`), every file through
  the same encrypted flow as the single-file upload.
- **Login banner.** The deployment's own notice - a demo-server
  warning - sits at the top of the login page and in the app's login
  form: `FXCLOUD_LOGIN_BANNER` (server side, editable in the unit at
  any time, no rebuild) rendered as `.server-banner`, HTML-escaped,
  empty knob = no element at all; the same text rides
  `GET /api/login-banner` for the app.
- **Account erasure (GDPR).** `DELETE /api/admin/users/{id}` takes
  the account and everything personal with it: files and versions
  (rows cascade, the bytes get unlinked), sessions, keys, passkeys,
  shares in both directions, public links, memberships. Group content
  refuses the erasure while any remains - it is the group's, not one
  member's to destroy - and the guards mirror the demote path: no
  self-deletion, never the last active administrator. The web's user
  administration gains the button behind a confirm.

## Server changes (this release is not just the app)

- `FXCLOUD_WEBAUTHN_ANDROID_ORIGIN` (comma-separated): the exact
  `android:apk-key-hash:...` values `login/finish` accepts beside
  the web's derived origin. Unset keeps the old behaviour byte for
  byte - but without it the app's passkey sign-in is refused.
- `GET /.well-known/assetlinks.json` serves
  `$FXCLOUD_DATA/assetlinks.json` when present (404 otherwise).
  Google Password Manager refuses the passkey prompt without that
  file: package name + the signing certificates (debug keystore for
  sideloads, Play's app-signing key for store builds).
- `FXCLOUD_LOGIN_BANNER`: the notice on the login page (and through
  `/api/login-banner` for the app). Editable in the unit at any
  time, no rebuild.

## Compatibility

API additions only; existing sessions, data and the web are
unaffected. The AAB ships as **versionCode 8** (above the closed
track's 5/6/7, an update either way; the14-day counter is untouched
- it tracks tester opt-in, not builds).
