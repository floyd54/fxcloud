# v0.2.0 - office documents in the browser (WOPI)

The first feature that needs a second process. Office files - docx,
xlsx, pptx, odt, ods, odp - now open in a browser editor instead of
staying inert rows: fxcloud speaks **WOPI**, the office engine (Euro-
Office, OnlyOffice or Collabora CODE) speaks it back, and the engine is
a URL the operator picks at deploy time, not a product the binary links
against. Nothing of this exists unless `FXCLOUD_OFFICE_URL` is set:
no routes, no CSP change, no UI - a default installation behaves byte
for byte like v0.1.6.

The design, the phase-0 spike (both Collabora and Euro-Office round
trips were proven against a WOPI stub) and the implementation notes
live in `concepts/office.md`; the full setup procedure - sizing rule,
the three network connections, reverse-proxy rules, the engine
container commands and troubleshooting - is a new section in
`INSTALL.md`.

## What changed

- **The WOPI host.** `POST /api/office/start` mints a session for a
  signed-in user after four gates (session, readable file, plaintext,
  PERM_UPDATE) and answers the target URL, a ten-hour HMAC-SHA256
  access token and the embed flow - never the secret. The
  `/wopi/files/<id>` family answers the engine's server-side calls:
  CheckFileInfo with byte-stable `Version`/`LastModifiedTime` (a value
  that drifts per read makes the engine discard local edits - found in
  the spike), GetFile under **both** content spellings (`/content` per
  spec, `/contents` per Collabora) and PutFile on the file path and on
  `/contents`, as PUT and POST. Every call re-checks live state, so a
  deactivated account, a revoked share or a trashed file cut an open
  editor off on its next request - and every token refusal (tampered,
  expired, wrong file, missing) answers the same `404`, never a hint
  that the id exists.
- **Version history survives autosaves.** The engine saves on every
  pause, which would shred `version_keep_n = 20` in one sitting.
  Decision 12: an office save pins the outgoing content unless *this
  session* wrote it, tracked as a bounded `(file, opened_at) ->
  modified_at` map - pre-session state and foreign writes (WebDAV,
  built-in editor) always land in history, the session's own
  intermediates do not. `save_streamed` gained the `pin_old` switch that
  drives both the quota delta and the pin; the editor save's behaviour
  is unchanged.
- **The editor overlay.** The engine URL reaches the page in a
  `data-office` attribute filled by the version-badge template slot -
  no config round trip. A shared `canOffice` gate (engine configured,
  plaintext row, UPDATE) drives the row click, the row-menu entry and
  the full-bleed overlay; the official WOPI host-page form POST and
  Collabora's query-string iframe are the two embed flows
  (`FXCLOUD_OFFICE_EMBED=form|iframe`). Three new strings in en, de and
  Klingon. The CSP widens `frame-src` and `form-action` for the engine
  origin only when configured, byte-identical when not.
- **Four environment variables** gate and steer the feature:
  `FXCLOUD_OFFICE_URL` (unset = off, and a stray secret/base/embed
  without it refuses to start), `FXCLOUD_OFFICE_SECRET`,
  `FXCLOUD_OFFICE_WOPI_BASE` for the engine's server-side address, and
  `FXCLOUD_OFFICE_EMBED`.
- **Documentation.** `INSTALL.md` gained the complete office section:
  the sizing rule (+4 GB covers all three engines; a 1-2 GB VPS runs
  without Office as a *supported* configuration whose documented answer
  is the WebDAV mount), the three-connection topology where the WOPI leg
  deliberately bypasses the reverse proxy, both engine container
  commands, proxy rules, a verification walkthrough and the troubleshooting
  found while spiking (the LXC sysctl refusal, the private-IP block).
  README carries the feature bullet, API.md the endpoint table,
  USERGUIDE the user-facing paragraph.

## Compatibility

Opt-in by construction: without `FXCLOUD_OFFICE_URL` the four WOPI
routes and the mint endpoint are not even registered, the CSP is
byte-for-byte v0.1.6, and the frontend attribute is empty. No migration,
no breaking API change - the only new dependency is `hmac`, which was
already in the lock tree. A default install upgrades in place like every
release before it.

## Tests

The suite grew by 37 checks to **795**, and the engine in them is curl -
the whole WOPI contract is plain REST, so CI needs no Docker: routes
absent while unconfigured, the mint's four gates, the secret never
leaking, the CSP widening, both GetFile spellings, and the decision-12
matrix live in the run (versions 1 -> 1 -> 2 -> 3 across
office/editor/office saves). `cargo test` grew by 5 to **71** (token
binding, tampering, expiry, document kinds, an RFC 4231 vector for the
HMAC). The real-engine smoke test is a documented manual procedure in
`INSTALL.md`.
