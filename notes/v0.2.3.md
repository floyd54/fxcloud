# v0.2.3 - install as an app (PWA), mobile view hardened

A short release between encryption milestones, two themes: the web UI
now installs like an app on phone and desktop, and the mobile layout
lost the last gaps found while testing it on real devices.

## What changed

- **Install as an app (PWA).** `manifest.webmanifest`, five icons from
  a dependency-free generator (`frontend/tests/gen-icons.js`, with a
  `--check` mode the suite runs, so committed art cannot drift), and
  `sw.js` - a service worker that exists for installability only: it
  passes same-origin requests through and **never touches the Cache
  API**, so an installed app can serve neither a stale shell nor cached
  response bytes (the suite fails on any `caches.` reference in it).
  Registration lives in the app and the login page; the share page
  deliberately offers no install.
- **Mobile view, hardened.** The topbar's fixed height and missing wrap
  meant five items could not fit a portrait phone, and the item pushed
  past the right edge was the user menu - Settings and Sign out became
  unreachable until the phone was rotated. The row now has auto height
  with a 56px floor and may wrap; on narrow screens the quota label and
  version drop (both live in Settings), long names ellipsize, and the
  menu stays pinned right. Further fixes from the device-gap list:
  long file names wrap inside their cell instead of being clipped by
  the panel, the editor toolbar wraps, tap targets grow under
  `pointer: coarse`, and every field gets 16px on touch devices (iOS
  Safari zooms the viewport into anything smaller on focus).
- **Docs/roadmap.** The sync agent moves back to demand-gated (phase 8)
  - "install our daemon first" is not a product a hosted cloud can lead
  with - while the shared Rust crypto core it motivated is promoted to
  phase 5 as the foundation of the native mobile apps (phase 7); the
  phase 1 WebDAV interim is now the standing desktop answer, and the
  WebDAV error no longer promises an agent that does not exist.

## Compatibility

Additive: one manifest, one worker, five icons, two routes
(`/sw.js`, `/manifest.webmanifest`), CSS in media queries plus one
topbar base rule - no API, format, session or crypto change. The
service worker is a passthrough by design, so traffic behaves exactly
as without one; instances that never install anything are unaffected.

## Tests

The suite grew by14 checks to **838**: manifest type and contents,
service-worker MIME and the no-cache invariant, PNG magic for every
icon over HTTP, generator-match via `--check`, manifest/apple-touch
links on both pages and their absence on the share page; `sw.js` and
the icon generator joined the parse list. `cargo test` stays at73.
Every gate (fmt, clippy with warnings denied, qjsc, call arity, i18n
parity across de/en/tlh) runs before the tests on every push.
