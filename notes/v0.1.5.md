# v0.1.5 - public links

The fourth work line (`concepts/public_links.md`): **a link is a bearer
credential**, not a session with a URL attached - whoever holds the URL
is whoever asks, no account and no sign-in on either side.
The owner mints a link on one entry of their own tree, hands out the
URL once, and can revoke it at any moment; the visitor gets a plain
page that reaches exactly the linked subtree and nothing else.

## What changed

- **Three presets on the share bitmask.** The share dialog gains a
  **Public link** section: preset (**Read - view and download**,
  **Add - upload only**, **Full - upload, download and delete**),
  expiry (**30/90 days after last use**, **30/90 days after creation**,
  **Never**), an optional **Label** and **Create link**. `add` is
  CREATE without READ: the visitor may drop files in but never sees a
  name, not even the folder's contents - the file-request behaviour
  falls out of the same `grants()` helper the user-to-user shares use.
  The server refuses any mask outside 1, 4 and 15, least of all a
  share bit: a link can never mint another link.
- **The token exists exactly once.** 32 random bytes, base64url
  without padding (43 characters), handed out in the `POST /api/links`
  response and never again - the database stores only
  `sha256(token)`, so a dump of the table yields no working link. The
  overview lists records only (label, preset, deadline, last visit,
  download count) with **Remove** to revoke; revocation is immediate
  and owner-only, a foreign id is a 404 without a hint.
- **The visitor surface.** `/s/:token` serves a static shell that
  resolves the link through `/api/public/:token/*` (meta, list,
  download, upload, delete-entry); no cookie anywhere, and every
  response carries `Referrer-Policy: no-referrer`, `Cache-Control:
  no-store` and `X-Robots-Tag: noindex`. Downloads are attachment-only
  and whole-file (no byte ranges on this surface), and every `?id=` is
  re-checked against the link's subtree per request - a sibling or a
  row above the shared root answers 404 without confirming it exists.
  A `full` visitor's delete lands in the *owner's* trash, and the
  shared root itself can never be trashed through its own link.
- **Expiry that behaves.** `rolling` (the default, 30 days) dies only
  after N days *without* use and slides forward to a full window on
  every successful visitor call - never backwards; the expiry check
  runs before the touch, so opening a dead link never revives it.
  `fixed` pins a deadline from creation that use never moves, `never`
  stores no deadline at all. While the row exists an expired link
  answers `410 Gone` (its own error code), and once the background
  sweep (the trash cadence) drops it the same token answers `404`.
- **Plaintext only in v1.** Minting on an encrypted row is refused
  with 409, and encrypted children of a linked folder never appear in
  a public listing - their ids answer 404, so a visitor cannot even
  learn they exist. Links over E2EE material (an envelope, or a
  fragment key in the URL) stay a later phase.
- **Metered by source address.** Unknown tokens spend a miss budget
  (20/min, checked *before* the lookup), successful resolutions a hit
  budget (600/min) and uploads their own (100/hour); spending them
  answers 429 with `Retry-After`. The counters live in memory (a
  restart forgives them the way it forgives ceremonies) and the
  source is the socket address - `X-Forwarded-For` is never trusted,
  so a reverse proxy belongs in front, not a header to believe.
- **Nine new routes** (3 owner + 5 visitor + the page), documented in
  API.md's new *Public links* section; the user guide gains a *Public
  links* subsection under Sharing, ARCHITECTURE.md's tree grows the
  three new files, and ENCRYPTION.md 7 records the plaintext-only
  line.

## Compatibility

Self-applying: one migration (`018_public_links.sql`) creates the
`public_links` table with its owner/source/expiry indexes, so
restarting the new binary is the whole upgrade. No existing endpoint
changed shape, no existing column was touched, and a browser sitting
on an open session needs no hard reload. The raw token exists only in
the one response that mints it - there is nothing to migrate and
nothing to leak.

## Tests

The suite grew by 82 checks to **755**: minting (43-char token, the
stored sha256, the raw token nowhere in the database, the defaults),
the token-less overview and its `file_id` filter, the refusal matrix
(non-preset masks including read|create, unknown expiry mode, day
bounds, label length, foreign owner 404, sessionless 401), the
visitor page's headers and i18n marks, subtree listings and downloads
(one level at a time, a file answers 400, outside answers 404,
attachment, ranges answered whole), the rolling slide and the owner's
never-touching operations, 410-then-404 across a sweep, the fixed
deadline byte-identical under use, the three presets end to end (add
may write but not look, full deletes into the owner's trash, the
shared root protected), the encrypted refusals (409 mint, hidden
children, 404 download), the group-folder backstop, revocation, and
the per-IP budgets (20 misses then 429 with `Retry-After`, no refill,
restart forgives). The unit tests grew by 14 to **66** (link records,
presets, sweep and the subtree walk in `db/link.rs`, plus the RFC 5987
round-trip in `public.rs`).
