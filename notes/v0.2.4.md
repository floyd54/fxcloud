# v0.2.4 - PDF preview on Android, service worker off the data plane

A bug report ("the PDF preview is broken on my Android phone, desktop
and iOS are fine") with two roots: a browser-platform limitation that
had gone untested until now, and a service worker scope from v0.2.3
that was broader than it needed to be. Both are fixed here.

## What changed

- **Android gets an open-PDF button instead of a blank frame.**
  Android's Chromium cannot render PDFs inside an `<iframe>` at all
  (only in top-level tabs), while desktop Chrome and iOS/WebKit embed
  them - the frame there was never going to show anything. The
  lightbox on such devices now says so and offers an explicit "Open in
  new tab" button: the tap is the user gesture `window.open` needs, and
  a top-level PDF - `blob:` or http - renders in Chrome's own viewer.
  One new i18n string in all three tables (de/en/tlh).
- **The service worker leaves the data plane.** v0.2.3's worker passed
  every same-origin request through; it now passes through only
  `/assets/*`, and only over http(s), with both guards pinned by suite
  checks. API calls, downloads, page navigations and `blob:` URLs (the
  decrypted PDF frame) never reach `respondWith()`, so no platform
  quirk of it - Android's PDF and download handling above all - can
  attach to them. The scope decision was verified against a real
  Chromium with fetch-event logging: on desktop Blink, `blob:` URLs
  fire no fetch events at all, so v0.2.3's broad passthrough was
  innocent on that engine but explicitly narrowed rather than argued.
- The no-cache invariant is unchanged and still suite-pinned: the
  worker never touches the Cache API
  ([ENCRYPTION.md](ENCRYPTION.md), section 11).

## Compatibility

No API, format, session or crypto change. The worker's scope only
shrank, which cannot affect anything except the worker itself; one new
i18n key in every table, one small CSS block, and the PDF fallback
codes to existing keys.

## Tests

The suite grew by2 checks to **840**: the worker's scope guards
(protocol + `/assets/`) and the Android PDF fallback in app.js.
`cargo test` stays at73. Every gate (fmt, clippy with warnings denied,
qjsc, call arity, i18n parity across de/en/tlh) runs before the tests
on every push.
