# v0.0.29 - baseline security headers on every response

Every response the server sends now carries a safety net that did not
exist before, closing audit finding F2 (see Audit.md in the repository).

## What changed

- `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN` and
  `Referrer-Policy: same-origin` on every response, UI and API alike.
- A `Content-Security-Policy` on every HTML page: scripts and frames
  from the same origin only, `frame-ancestors 'none'` (no page can
  embed the login form anymore), `base-uri 'self'`, `object-src 'none'`.
  Inline styles stay allowed because the UI uses them; images may come
  from `data:`, `blob:` and `https:` for externally referenced pictures.
- `Strict-Transport-Security` (180 days) whenever the deployment
  declares HTTPS - via `FXCLOUD_ORIGIN` or an `X-Forwarded-Proto`
  header from a reverse proxy. Plain-HTTP installs never get it.
- The file preview keeps its own stricter sandbox CSP; the new header
  layer only fills in what a route did not set itself.

## Why it matters

The app was XSS-clean at review time, so this is the missing safety
net rather than a hole being plugged: one future mistake would have
executed with nothing to blunt it, and today any page could have
framed the login form as a clickjacking nuisance at minimum.

## Action required

None. HSTS appears by itself once the origin is HTTPS; note that
browsers remember it for half a year, so an HTTPS install that later
moves back to plain HTTP on the same name will be hard to reach.
