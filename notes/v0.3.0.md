# v0.3.0 - the format gets one implementation

Phase 5 of ENCRYPTION.md ships. The browser still runs its JavaScript
twin unchanged, but the client-side crypto now exists once, in Rust,
for everything that is not a browser tab: the container format, the
account-key layer and the share envelopes live in `crates/fxcrypto`,
pinned to the JS reference by shared golden vectors - three readers
over the same committed bytes on every CI run (the JS implementation,
the Rust twin, and the C ABI the native apps will call). This is the
foundation phase 7 (native apps) was waiting for; no app ships here.

## What changed

- **`crates/fxcrypto` - the shared core.** FXE1 container (header,
  chunking, row-bound AAD), the account-key layer (Argon2id KEK with
  stored parameters, wrap/unwrap records under seven domain-separated
  AAD labels, unlock, recovery, passphrase rewrap, child keys,
  fingerprints) and the share envelopes (ECIES: ephemeral ECDH in the
  recipient's suite - X25519 first, P-256 fallback - HKDF-SHA-256,
  AES-256-GCM, one unified failure message by design).
- **Golden vectors in both directions.** `tests/fixtures/fx1-vectors.json`
  (13 cases) and `fx-keys-vectors.json` (27 cases) are written by the
  spec-side generators and read by every implementation: a drift in any
  one of the three turns CI red. The JS write sides stay roundtripped
  in crypto-roundtrip.js as before.
- **`crates/fxcffi` - the C ABI.** `fxcffi.h` is the boundary contract:
  ownership rules, one stable error code per failure variant, panics
  stopped at the edge. A real C program compiles against the shipped
  header with `-Werror` and links the built static library on every
  suite run; the Kotlin/Swift bindings arrive with phase 7.
- **Docker warm layer** now resolves the whole workspace, so CI caches
  the dependency layer across member changes.

## Compatibility

No user-visible or API change: the browser runs the same fxcrypto.js,
the server is unchanged and stays key-blind (the suite pins that
neither crate ever enters the server's dependency graph), and existing
data opens exactly as before - the Rust twin reads what the JS wrote,
proven by the vectors rather than promised.

## Tests

The suite grows by 6 checks to **851** (both vector readers and the
C ABI smoke test), `cargo test` runs 86 tests, and every gate (fmt,
clippy with warnings denied, workspace tests, the full suite, the
Docker build) runs on every push. The release binary is the same
static musl build as always.
