# v0.4.5 - the user menu, in-app help, and fingerprint unlock

The header grows up to the web's shape, the guide comes in-app, and
the sensor becomes a way into an encrypted account:

- **Header, web-shaped.** Settings and Logout leave the header links
  and sit behind the account name in a user menu (Settings, Help,
  Sign out - the web's dropdown minus the admin entry, which stays
  web). Trash becomes a one-tap icon (Material's delete glyph in the
  header's link blue).
- **Help in-app.** The server's own `/help` guide in a script-less
  WebView (the page ships without scripts, so JavaScript, DOM
  storage and file access stay off), language from the device
  (`?lang=`), the page's own back stack under the shared back
  gesture, destroyed on release.
- **Fingerprint unlock.** A switch beside auto-unlock: one
  BiometricPrompt seals the ARK under an auth-bound AndroidKeystore
  key (strong biometric per use on API 30+, a 30-second window
  below), stored as `biodevice.<id>` in the auto-unlock's shape. The
  passphrase pane shows "Unlock with fingerprint" and asks on its
  own the first time it appears; success adopts the session exactly
  like the silent device blob (openShares included). The passphrase
  field stays visible and always works - the sensor is a
  convenience, never the only door. Enrolling new fingerprints
  invalidates the key; the failed attempt drops the blob with a
  notice to set it up again. `MainActivity` now extends
  `FragmentActivity` (androidx.biometric requires it; it is a
  ComponentActivity, so Compose, the activity-result APIs and the
  back dispatcher are unaffected).
- **Passkey trust, fixed at the root.** Google refuses the prompt
  when `assetlinks.json` does not name the installed certificate -
  and CI's release APK signed with the runner's ephemeral debug
  keystore, a different fingerprint every build. The debug keystore
  now travels in the repository: this machine and CI sign every
  debug build with the same certificate, so this release's debug
  APK is covered by the deployment's assetlinks from the start
  (which now lists all four paths: local, the v0.4.4 release APK,
  Play's classic and post-quantum keys).

## Compatibility

The server binary is unchanged apart from its version string; no
API, no data, no manifest change. The AAB ships as **versionCode 9**
- above whatever the closed track holds, an update either way; the
14-day counter is untouched (it tracks tester opt-in, not builds).

## Tests

Suite **892**, `cargo test` (workspace) **97**, the JVM vectors at
**16**. The fingerprint path is device-side - the Keystore does not
exist on the build host, so there is no suite pin and no JVM test:
the passphrase pane's fallback is the guarantee. `lintRelease`
gates the bundle.
