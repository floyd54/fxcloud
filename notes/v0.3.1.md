# v0.3.1 - re-key, rotate, encrypted names - and a help page

A patch release by size, not by ambition: day to day the app looks and
behaves exactly as before, but the key menus gained three deliberate
actions and the top bar a Help entry that opens the whole user guide in
your language. Under the hood this rides on the shared Rust crypto core
that v0.3.0 shipped - the format now has one implementation for the
browser, for the apps to come, and for the C ABI they will call.

## What changed

- **Re-key a folder** (folder menu, and offered explicitly after you
  revoke a share): a fresh key for the folder and every folder below it,
  every child record re-wrapped, and every remaining grantee's envelope
  re-sealed - the revoked grantee's old key opens nothing new
  (ENCRYPTION.md 5.6, DECISION 4). File keys stay as they are: what a
  former grantee already saved keeps opening, which is the documented
  line between "copies they had" and "anything new".
- **Rotate a file key** (file menu): the content is re-encrypted under
  a fresh key in a single save. The version history goes with it, said
  out loud in the confirmation - old versions were written under the old
  key and could never open again (DECISION 5, versioning E2). The file's
  share envelopes are re-sealed to the new key.
- **Encrypt names** (folder menu): a per-folder flag that wraps the
  names below it under their parent key, so the server stores blobs
  where it used to read words. Flagging walks the subtree (wrap first,
  flag after, cancellable and resumable); WebDAV renames, public links,
  visitor uploads and copies answer with a clear refusal inside flagged
  paths, the office editor gets a synthetic name from the MIME type,
  and a share's mount label travels wrapped in the envelope's key. The
  trade-offs are written down in concepts/names.md: sizes, times,
  structure and the approximate name length stay visible - this lifts a
  corner of NG1, not all of it.
- **Help in the user menu**: the complete user guide as a page at
  `/help`, in English, German and Klingon, following the language the
  UI is set to (or `?lang=`). No account needed - a reader who cannot
  sign in can still reach troubleshooting.

## Compatibility

No breaking changes: every new action is opt-in and lives in the row
menus. Unflagged folders behave exactly as before - plaintext shares,
WebDAV and the office editor are untouched outside flagged paths. The
crypto core stays invisible to the API: the server remains key-blind
(the suite pins that neither crate ever enters its dependency graph),
and the browser still runs fxcrypto.js, now cross-checked against the
Rust twin by shared golden vectors on every CI run.

## Tests

The suite grows by 34 checks to **879** since v0.2.7 (golden vectors
for the container and the key layer, the C ABI smoke test, the re-seal
endpoints, the names-flag cascade, the guide served in three languages);
`cargo test` runs 90. Every gate (fmt, clippy with warnings denied,
workspace tests, the full suite, the Docker build) runs on every push.
